# Definition of Done

> A story is **Done** when ALL of the following criteria are met.
> This list should be agreed upon by the whole team before Sprint 1 begins.

---

## Code Quality

- [ ] Code has been reviewed by at least one other team member before merge.
- [ ] The implementation follows the project’s agreed conventions and is free of unnecessary complexity or duplicate logic.
- [ ] No hardcoded values are introduced where configuration, constants, or environment-based values are appropriate.

## Testing

- [ ] All acceptance criteria for the story or task have been manually verified, or automated tests have been added/updated where applicable.
- [ ] No known bugs or regressions were introduced by the change.
- [ ] Any required validation steps for the feature or fix have been completed and documented as needed.

## Documentation

- [ ] README or relevant project documentation has been updated if setup, usage, workflow, or behavior changed.
- [ ] Any required notes for future maintainers are clear and accurate.

## Version Control

- [ ] The work is completed on a feature/fix/docs branch and merged into `main` through a pull request.
- [ ] Commit messages follow the project’s conventional commit format: `feat:`, `fix:`, `docs:`, `chore:`, or `refactor:`.
- [ ] The branch is clean, the final changes are reviewed, and there are no unresolved issues blocking completion.
